看懂、会做、能改进

把 GPT-6 Astra 留作可替换的高层“大脑”，用示教记忆提供上下文，以技能和兼容的 VLA 作为“小脑”，再由独立安全层把每个动作限制在已校准的范围内。

Existing stack

Embodiment

SO-101 + 相机

Independent safety plane · always on

安全监督器与人工接管

新鲜度、维度/顺序、限位、每步变化、动作时长、急停状态检查。任何故障默认拒绝新命令、停止或保持，并转人工判断；监督器不接受大模型覆盖。

独立于模型的硬边界硬件急停 / 电源隔离、驱动器限位、工作空间、低速试运行和 watchdog 必须在 SO-101 backend/控制器侧成立；Python 检查只是第二道门。

脑、小脑和技能怎么分工

分层是工程边界，不要求模仿生物结构。控制周期中避免让云端大模型逐帧决定电机；它做稀疏的任务级决策，低层按稳定频率闭环。

大脑 · GPT-6 Astra (可替换)

只产出有限的计划和技能调用

  • 把“把积木放进盒子”拆成已注册的技能。
  • 通过 ICL 读 1–3 条相似、获准使用的示教摘要或短片。
  • 收到技能结果后选继续、换技能、暂停或求助。
  • 不拿到串口、不生成任意 shell、不直接写关节值。
小脑 · 技能执行 + VLA Router

可以接多个 VLA，但按兼容性路由

  • 每个模型实现同一个 PolicyAdapter，并声明支持的 SO-101 embodiment、相机模态、动作 schema、技能、延迟与版本。
  • 每个动作段选择一个兼容策略；没有匹配项就安全停止，不静默切换到别的机器人模型。
  • VLA 输出仍需 safety supervisor 校验，再交 SO-101 adapter。
  • HoloBrain 可保留在 registry；需先有 SO-101 数据、动作映射和专用验证结果。
推荐框架：沿用 RoboOrchard 的 typed policy/session 与评测，把 PyRUA-Lean 的“短程序组合原语、检查结果、局部重试”改造成白名单技能；参考 uni-robot-agent 的统一工具/后端接口。先集成接口，不引入整套外部运行时，减少 SO-101 驱动和现有依赖冲突。

录视频示教、上下文学习和数据管理

可以录一段视频帮助模型理解过程，但训练精准动作策略需要把视频与机器人动作、状态和时间对齐。只存 MP4 不知道每帧对应什么电机动作。

采集示教

人工 teleop；同步 RGB、关节位置/速度、夹爪命令、动作时间戳、任务指令和人工标注。

质量检查

检查掉帧、时钟漂移、校准 ID、动作维度、碰撞/失败标签；质量不合格的 demo 不进入 ICL 索引。

检索上下文

用任务/物体/场景/成功状态检索少量片段；给 GPT-6 Astra 看步骤和关键帧，不传整个视频历史。

稳定性、安全和人工介入

把失败当作正式状态。对实体 SO-101，未知执行结果不能自动重放；急停或校准错误后必须由人确认恢复。

情况运行时动作人工处理
相机帧过旧、时间戳错位、状态缺失不发新动作；安全停止并写入 telemetry检查相机、线缆、同步；确认新 observation 后才恢复
关节顺序/维度/单位不匹配、NaN、越界或变化过大在写电机前拒绝整个 action chunk；不做静默裁剪检查 adapter、标定和模型卡；必要时在低速台架重标定
模型超时、连接断开或执行回执未知禁止自动重放；停止请求并保持/撤销使能确认机械臂位置与夹持状态，再选择继续、回零或终止
技能无进展、抓取失败、物体状态不确定不自动重发动作；先拿新 observation，再由大脑选择已验证的 recovery skill执行回执未知或状态不明时暂停 episode，由人工选择继续、复位或终止
触发急停、碰撞、限位、温度/电流异常硬件侧 stop；锁住自动重启，记录硬安全事件人工检查并显式复位；该 episode 不计作自动成功

上线前的独立保障

  • 急停与电机 disable 能独立于 GPT/VLA 服务工作。
  • 首轮 profile 从真实 SO-101 校准导入，绝不猜 joint order/单位/软限位。
  • 起始动作 chunk 只放 1 步；通过仿真与台架评测后再逐级放大。
  • 设备、相机、模型健康检查不过就不进入控制态。

接管界面应显示

  • 任务目标、当前技能和预期后置条件。
  • 实时相机帧、当前关节状态、最近动作与回执。
  • 暂停、软停止、硬件急停状态、继续/失败/人工完成按钮。
  • 操作者、接管原因、修复动作和是否允许作为示教数据。

已落到工程里的代码入口

当前是可扩展的安全骨架。模型密钥、摄像头、LeRobot 串口、SO-101 校准和评测环境没有在这里伪造配置；接好真实硬件信息后再实现具体 adapter。

contracts.py + interfaces.py

Observation、ActionChunk、SkillCall，以及 Brain / DemoMemory / VLA / Robot 接口。

policy_router.py + policy_chunk.py

按 embodiment、观测模态、动作 schema 和技能能力路由；只注册 verified skill。

safety.py + adapters/so101.py

关节单位/顺序、观测新鲜度、动作步数和校准限位检查；初始 SO-101 backend 每次仅收 1 步。

runtime.py + episode_store.py

一个新 observation 对应一个技能决策和动作块；错误或回执未知时停机并留下 append-only JSONL 事件。

rsi.py + skill_registry.py

固定 episode/seed 对比、零硬安全事件、成功率/时延门槛和显式人审；通过后仍需独立操作切换 artifact。

README.md + SO-101 安全配置模板

关节名和限位为空，故意不能放行动作；必须从实机驱动与校准读取，不猜测。

这个工程的 RSI 怎么写

参考 ENPIRE 的 reset–execute–verify–record–refine 和 ASPIRE 的“技能精炼式学习”：先冻结评测环境，再改策略侧。第一版 RSI 不改权重、不改 verifier、不改安全阈值，也不在线自我更新。

1

固定 baseline 和任务切分

保存当前 SO-101 adapter、skills、model、prompt、calibration 的哈希；固定开发 seed 与 held-out seed。独立 verifier 决定成功，Agent 看不到真值捷径。

2

记录所有成功、失败和中断

保留视频、动作、状态、失败码、工具回执与人工干预；失败不删除、不伪装成模型完成。

3

提出可证伪的小改动

GPT-6 Astra 离线分析失败簇，只改一个技能、检索策略、prompt 或路由规则；写 hypothesis、diff、预期指标和回滚点。

4

隔离运行与分层评测

静态检查 / sandbox → Isaac 仿真固定 seed → 未见 seed → 人工批准的 SO-101 shadow mode → 少量 canary。候选和 baseline 用同场景、同 reset、同 verifier。

5

安全门槛优先于成功率

任一硬安全事件直接拒绝；比较成功率、失败类型、p95 latency、人工介入率和成本。达到样本数且无回归后还要人工审核，才能升级 registry。

6

版本晋级与一键回滚

candidate manifest 记录代码、模型、技能、数据与评测哈希。稳定版只切换版本指针；出错即回退上一签名版本，不自动在线覆盖。

每次 RSI 只允许策略侧变化。reset、verifier、seed、SO-101 限位、急停合同和数据 schema 均只读；否则前后成绩不可比较。

从现在到 SO-101 上机

先把硬件和数据契约做正确，再接 GPT 和 VLA。现有 Panda HoloBrain 模型不能直接作为 SO-101 controller。

A

盘点硬件与只读检查

确认 LeRobot/驱动版本、端口、关节数量和命名、单位、摄像头 ID、校准文件、急停/失能方式；先只连接并读状态。

B

人工遥操作与录制

实现 SO-101 backend；低速 teleop 采集 20–50 个短 episode，验证视频/动作/关节时钟对齐、reset 和安全停机。

C

只实现 3–5 个原子技能

observe、approach、grasp、lift、place；每项明确前置条件/成功证据/超时/失败恢复。先在桌面已知物体和低速条件完成闭环。

D

接入 GPT-6 Astra + ICL

大脑只可调用注册技能；先 dry-run，再 shadow mode 比较计划与人工操作。GPT 供应商通过 provider interface 可替换。

E

训练或接入 SO-101 VLA

用动作对齐的 LeRobot episodes 训练/验证；模型卡声明 embodiment 和 action schema。未知兼容性模型不会进入路由候选。

F

开启离线 RSI，再小流量实机

固定 seed 与 verifier 后跑候选比较；人工批准安全、成功率、时延均达标的版本，再以短 episode、低速和操作者在场做 canary。

论文与开源代码：采用什么、为什么

不整套搬入多个框架。复用本项目已有的仿真、policy/session 和数据转换；借鉴开源项目里的边界设计，减少 runtime 与 SO-101 驱动的依赖耦合。结果数字均为论文/项目报告，需按同一任务复现。

uni-robot-agent · harness 结构

统一工具合同，隔离 agent、orchestration、service 和 robot backend。采用其模块边界，不直接绑定 Codex/Claude runtime。
